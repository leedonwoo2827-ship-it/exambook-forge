# 재집필 규칙 (저작권 안전 · 실전 품질)

원본은 **타 출판사 기출문제집**이다. 자사 모의고사는 **개념·난이도·키워드는 실전 수준으로 유지**하되
**표면을 전면 재작성**하여 파생 저작물 이슈를 피한다.

## 1. 저작권 안전 재집필 (필수)

원본에서 **개념·유형·난이도만** 취하고, 아래는 **전부 새로 쓴다**:
- 문제 지시문 문장 (같은 개념이라도 다른 문장·다른 각도로)
- 지문의 **테이블명·컬럼명·데이터 값·행 수** (예: `Mytest`/`EMP` → `사원_서울`/`주문내역` 등 새 소재)
- SQL 예제의 구체 값·별칭·조건
- **보기 4개 문구와 오답(distractor)** 구성
- 등장인물/소재(예: 원본 "조조·유비" → 다른 인물/사물 세트)

**금지**: 단순 패러프레이즈(문장만 살짝 바꾸기), 값 몇 개만 교체, 보기 순서만 섞기.
→ "다른 형태의 집필"이 되도록 시나리오 자체를 새로 구성한다.

## 2. 출제 순서 변경 (필수)
- 개념을 원본 문항 순서대로 나열하지 않는다. `sqld-syllabus.md`의 개념을 **섞어** 배치.
- 과목 경계(1~10 = 1과목, 11~50 = 2과목)는 유지.
- 3개 회차는 서로 다른 흐름·다른 하위주제 강조로 차별화.

## 3. 문항 품질 기준
- **정답은 하나로 명확**. 복수정답/무정답 금지.
- **오답(distractor)은 그럴듯하게**: 흔한 오개념·비슷한 문법·경계 조건을 노린다(무의미한 보기 금지).
- 계산/실행결과 문항은 **실제로 검산**해 정답을 확정(행 수, 집계값, 정렬결과, 조인건수 등).
- SQL은 **문법적으로 유효**해야 하며, DBMS 특이사항(Oracle vs SQL Server)은 해설에 명시.
- 부정형("올바르지 않은 것")과 긍정형을 섞되, 지시문에 부정어를 굵게 또는 명확히.

## 4. 난이도 루브릭
| 난이도 | 기준 |
|---|---|
| 하 | 단순 정의·분류 암기, 1단계 함수 결과 |
| 중 | 2~3단계 추론, 표/SQL 해석, 문법 적용 |
| 상 | 다단계 실행 추적(계층·윈도우·조인건수·NULL경계), 동치 변환, 함정 포함 |

회차 난이도 분포 목표: 상 12~16 / 중 24~28 / 하 8~10 (합 50).

## 5. 키워드(tags) 규칙
- 문항당 **2~4개**. 요약노트·검색 연결의 축이 되므로 **개념 표준어**를 쓴다.
- `sqld-syllabus.md`의 tags 예시와 일관되게(예: `계층형 쿼리`, `CONNECT BY`, `집합 연산자`, `WINDOW`, `OUTER JOIN`).
- 과목 대분류가 아니라 **세부 개념** 위주.

## 6. 정답 분포
- 한 회차에서 `answer_index` 0/1/2/3(①②③④)이 특정 값에 쏠리지 않게(각 8~17개).
- `build.py --stats`로 분포를 확인하고 필요 시 재배치.

## 7. 그림/도형 (SVG를 많이 쓴다)
- 그림은 PNG 대신 **인라인 SVG**로 만든다(`svg-conventions.md`). 확대·편집·재사용에 유리.
- **그림 의존 문항 전용이 아니다.** 문제·지문뿐 아니라 **해설의 개념 시각화**에도 적극 사용
  (조인 벤다이어그램·계층 트리·정규화 흐름·윈도우 프레임·실행순서·집합연산 등). 문항당 여러 개 가능(`assets[]`).
- "실행결과 스크린샷"류는 결과 표를 마크다운 표로 직접 제시(스크린샷 재현 불필요).
- 요약노트·이론에서도 동일 SVG 규약을 재사용한다(추후 용도 확장 전제).

## 8. 검수 추적성
- 각 문항 `derived_from`에 원 개념 근거 문항 id를 남긴다(예: `01-18`).
- 이는 저작권 회피 확인이 아니라 **개념 커버리지 점검**용(원본의 어떤 개념을 다뤘는지 매핑).

## 9. 해설 · 낭독본 — 보이는 텍스트 ↔ 들리는 텍스트 (영상 파이프라인 필수)
영상(파이프라인 #3)은 **원문은 화면/자막**으로 보여주고 **낭독본은 TTS**로 읽는다. 두 텍스트를 분리한다.
- `explanation`(화면·자막): **원문 표기 그대로**. 예: `시각`, `1.2%`, `3,000원`, `SELECT *`. 정답 근거 + 오답이 틀린 이유, 계산 과정 포함.
- `explanation_speech`(낭독, **권장**): **소리나는 대로 발음 표기**로 직접 작성.
  - 예: `시각`→"시깍", `1.2%`→"일 점 이 퍼센트", `3,000원`→"삼천 원", `CONNECT BY`→"커넥트 바이",
    `NVL`→"엔브이엘", `10.5`→"십 점 오", `COUNT(*)`→"카운트 스타".
  - #3의 발음사전은 짧은 어휘/단위만 치환 가능 → **대소리·소수점·복잡한 수/기호 낭독은 #2(집필)가 책임**.
- 필요 시 `narration_question`/`narration_answer`로 문제/정답 낭독본도 발음 표기로 제공.
- lesson JSON 텍스트 필드는 **순수 텍스트**여야 하므로, 낭독본에도 마크다운(`**`,백틱,`![]()`)을 넣지 않는다.
